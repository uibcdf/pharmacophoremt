# Prepare saved-inspection usability receiving

## What and why

Deliver a downloadable public-writer synthetic fixture, participant tasks,
separate facilitator answers and unfilled observations. Real novice and API users
need the same small complete inspection task and explicit error-recovery criteria.
Technical parity is preparation, not evidence of unaided human usability.

## How

Compose supported public writer/reader and real CLI operations. Keep synthetic
records explicit, every original status/identity and pending attempt distinction.
No runtime helper, collection/parser, schema/index or scientific calculation.
Registered support/diagnostic contracts remain owned by the existing public
reader; the application setup script uses argparse for its one directory input.
There is no new library argument, quantity, optional-engine or attribution boundary.

## Alternatives and limits

Do not ask participants to run a molecular calculation or copy private original
files. Do not count scripted task success as representative human usability.
No provider/new package/environment transaction or stopped #148/#165 retry.

## Acceptance criteria

Reproducible fixture using public operations; original documented setup/CLI/API
bodies dry-run from source and unchanged owned artifact; expected refusal with
no fixture mutation; participant/facilitator/unfilled-observation separation;
strict docs/download/navigation and local reporting/format checks. Full source,
public/platform, human/scientific/performance/release gates remain independent.
