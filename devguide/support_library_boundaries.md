## Optional-attribution diagnostic failures

[#72](https://github.com/uibcdf/pharmacophoremt/issues/72) corrects an uncovered
host failure boundary. Normal PHMT-W102 emission still uses SMonitor's public
catalog machinery. Promotion of that exact warning to an exception is handled
without replacing science. Unexpected warning construction/emission failures
instead append an error record with operation `emit attribution diagnostic`,
the diagnostic reason, `tracking_operation` and `tracking_reason`.

A plain JSON stderr record uses the existing catalog code and these fields,
without re-entering a failed emitter or copying a renderer. If output also fails,
`fallback_error` remains in the detached payload. Capture stays `failed` with
no complete bibliography. Completed results and original scientific exceptions
keep their scientific contract; failed payloads cannot be rendered as complete
reports. No attribution schema, provider floor or public signature is changed.

The durable guards are
`tests/test_attribution.py::test_unexpected_attribution_diagnostic_failures_are_visible`
and
`tests/test_attribution.py::test_broken_attribution_diagnostic_output_preserves_result_and_original_error`.
They use real native recognition and application sessions, fault both warning
construction/emission under ordinary and warnings-as-errors policies, and retain
science when fallback output is unavailable. Existing attribution/contract guards
continue to protect normal capture, absence, warnings, units and saved references.
